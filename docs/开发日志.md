开发日志（AmbientVoiceSubtitles / NPC随口台词头顶字幕）
=====================================================

这份是给人看的来龙去脉，重点记「为什么是这样」而不是「代码长什么样」。
代码结构见 docs/ARCHITECTURE.md。

v1：为什么第一次尝试必然崩
--------------------------
思路很直接：截获台词，然后调引擎自己的
gCGUIEntityRenderer::AddScreenMessage 把字画在 NPC 头顶。

结果一进游戏就 0xC0000005。反汇编发现 AddScreenMessage 的第一件事是
call eCGeometryEntity::GetWorldMatrix(实体) —— 我传进去的是 NULL，当场访问违例。
教训：这个 API 要的是「几何实体」（eCGeometryEntity），脚本层的 Entity* 不是它，
必须先 eCEntity::GetPropertySetCount / GetPropertySetAt →
eCEntityPropertySet::GetGeometryEntity() 转过去。

v2：找对实体
------------
从真实 bark 到来时的脚本实体出发，遍历属性集拿几何实体，拿到了再调
AddScreenMessage。所有调用各自包 SEH：任何一步失败只写日志，绝不让插件把游戏带崩。

随之而来的第二个问题：AddScreenMessage 投出去的消息是「每帧被消费」的，
投一次只闪一帧。于是改成维护一个队列，并挂 gCGUIEntityRenderer::OnBeginFrame
的虚表槽，每帧把队列重投一遍。这一步之后字幕才真正稳定停留。

文本数据：从 json 到直接读游戏
------------------------------
最早的版本带一份自己导出的文本库（svms_zh.json，由汉化包的 svms 表导出），
安装时复制到 bin 旁边。问题是：文本和汉化版本绑死，游戏一换语言/换汉化就过期，
而且等于插件自己发行游戏文本。

后来改成直接读游戏自己的 data\compiled\strings.pak：
- 解析 G3V0 归档，取 svms.tab；
- 表项可能是 zlib 压缩的，所以源码里带了一份最小 inflate（不依赖 zlib.dll）；
- 解析 TAB0 多语言表，按当前游戏语言取对应列。

好处是插件不含任何游戏文本，跟随游戏语言，汉化包更新也不用动插件。
旧的 json 读取路径保留成兜底（pak 读不到时才用），只为兼容老安装。

v17：语言要跟着游戏走
--------------------
pak 里的文本是多语言列。Language=auto 需要问引擎当前语音语言，用的是
eCLocAdmin2::GetInstance / GetVoiceLanguage。注意取值时机：要在引擎文本子系统
起来之后取，否则拿到的是默认值。运行中玩家改语言时，发现列名变了就重新读 pak。

v19：懒加载（最贵的一次教训）
----------------------------
早期的读取放在 DllMain 阶段。结果：插件抢在引擎前面拿下 strings.pak 的句柄，
还提前碰了 eCLocAdmin2，主菜单的文字直接回退成 HUD2_Label_PressStart 这类 ID。
玩家进游戏才发现，而 Risen 启动很慢，试错成本很高。

改法：DllMain 只起线程；文本推迟到「第一次真的要显示字幕」时才读（ensure_text）。
线程里只做模块探测和挂钩，等 Game/Engine 等模块齐了再干活。

v20：缺 ini 时生成的默认 ini 必须是「当前这一份」
-----------------------------------------------
「ini 不存在就自动生成一份」的文案，原来是手写死在 .c 里的一份副本。
改 ini 时那份副本不会跟着变，于是它一直写着 FadeStartM=5、French_Text 示例，
而真实 ini 早就是 10 了。

改法：文案不再进源码。tools/gen_ini_template.py 把 config/AmbientVoiceSubtitles.ini
逐字节转成 src/ini_template.h（C 字符串数组），编译进 asi。
ini 是唯一来源：改 ini → 重跑生成器 → 重编译。生成的头部还带一个编译期检查，
数组小于 512 字节直接编译失败，防止生成器读错文件后悄悄写出一份半截 ini。

踩过的坑
--------
- 二进制里内嵌模板要和 ini 逐字节相同才算过；比对时要在整个文件里搜一遍，
  确认只有一份、且字节完全相等（顺便确认旧文案 FadeStartM=5 一次都不出现）。
- zig 0.17 的 `zig cc` 不认 --cache-dir，要用 ZIG_LOCAL_CACHE_DIR /
  ZIG_GLOBAL_CACHE_DIR 环境变量。
- 交付前必须离线验：代码类交付不能「编译通过就发」，尤其这个游戏每次试错都要
  重新启动、加载很慢。
