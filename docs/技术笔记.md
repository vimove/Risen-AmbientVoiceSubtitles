# 架构与维护者笔记

[English](ARCHITECTURE.md) · **简体中文**

这是一份「怎么做、为什么这么做」的文档，给想修或想扩展这个插件的人看。整个插件就是一个
C 文件（`src/AmbientVoiceSubtitles.c`）；没有外部依赖，也不用 C++ 运行时。

插件从游戏里要的一切都**按修饰名**在运行期解析（`GetProcAddress` / 改导入表），所以它不
依赖固定地址或偏移，只要导出符号不变，游戏重新编译后照样能用。**没有**特征码扫描，也没有
硬编码 RVA。

## 加载模型

1. Ultimate ASI Loader 把 `AmbientVoiceSubtitles.asi` 当普通 DLL 加载。
2. `DllMain` 只起一个 `init_thread`，完全不做引擎相关的活（见 [踩过的坑](#踩过的坑)）。
3. `init_thread` 读配置，然后轮询 `Game.dll`、`SharedBase.dll`、`Script.dll`、
   `Script_Game.dll`、`Engine.dll`（300 ms 一次，最多约 36 分钟）。
4. 每出现一个模块，就解析下面那些符号、装上两个导入表挂钩。必需的那一组齐了以后，它给
   模块列表拍个快照（用来在日志里区分引擎内存和 mod 内存），再挂渲染器虚表，然后线程退出。

## 挂钩

### 1. `Entity::StartSaySVM` —— 「有人开始说话了」

```
?StartSaySVM@Entity@@QEAAXAEAV1@VbCString@@_N2@Z      (Script.dll, imported by Script_Game.dll)
```

在 `Script_Game.dll` 的导入表里改。`this` 是说话的实体，`bCString` 是 svm 名。挂钩把两者
都拷进一个 16 槽的环形缓冲（`push_recent`，带 `GetTickCount` 时间戳），然后调原函数。

### 2. `gCSvmAdmin::FormatSampleTitle` —— 「马上要播的是哪条字幕」

```
?FormatSampleTitle@gCSvmAdmin@@QEBA_NAEBVbCString@@0AEAV2@@Z   (Game.dll, imported by Script.dll)
```

在 `Script.dll` 的导入表里改。挂钩先调原函数，然后

- 读 `voice` 和 `svm` 两个 `bCString` 参数（用 `ReadProcessMemory`，它就是一个安全的读，
  指针坏了也不会崩）；
- 拼出查表用的键 `SVM_<voice>_<svm>`；
- 在已加载的 `svms` 表里查这个键；
- 找最近 1500 ms 内登记过、svm 相同的说话者（`find_recent`）；
- 把文本排进绘制队列（`show_text`）。

键或说话者缺一个，就记 `NOKEY` / `NOSPEAKER`，什么都不做 —— 少一条字幕永远不会是致命错误。

### 3. `gCGUIEntityRenderer::OnBeginFrame` —— 每帧绘制的入口

```
?OnBeginFrame@gCGUIEntityRenderer@@UEAAXPEAVeCGuiDevice2@@PEAVeCSprite@@@Z
```

`AddScreenMessage` 投出去的消息每帧都会被渲染器消费掉，所以插件不能「投一次就不管」。它挂
的是渲染器实例的 `OnBeginFrame` **虚表槽**（实例来自 `gCGUIEntityRenderer::GetInstance()`）：
挂钩先把队列里现有的内容用 `gCGUIEntityRenderer::DrawScreenMessage` 画完，再调原版
`OnBeginFrame`。

槽的位置靠扫虚表前 128 项、找 `OnBeginFrame` 的地址确定，然后 `VirtualProtect` + 换指针。
挂钩只装一次。

### 用到的引擎 API

| 符号 | 用途 |
| --- | --- |
| `gCGUIEntityRenderer::AddScreenMessage` | 投一条锚定在世界坐标上的消息 |
| `gCGUIEntityRenderer::DrawScreenMessage` | 画一条已排队的消息（在每帧挂钩里调） |
| `gCGUIEntityRenderer::GetInstance` | 渲染器实例 / 虚表 |
| `bCUnicodeString::bCUnicodeString(wchar_t*)` | 构造字符串参数 |
| `eCEntity::GetPropertySetCount` / `GetPropertySetAt` | 遍历属性集 |
| `eCEntityPropertySet::GetGeometryEntity` | 脚本实体 → 几何实体（`AddScreenMessage` 要这个） |
| `eCGeometryEntity::GetWorldMatrix` | 头顶位置 |
| `Entity::GetPosition` | 算淡出用的距离 |
| `eCApplication::GetInstance` / `GetCurrentCamera` / `GetMainCamera` / `AccessPosition` | 淡出用的相机位置 |
| `eCLocAdmin2::GetInstance` / `GetVoiceLanguage` | `Language=auto` |
| `gCHudModule2::GetSystem` / `gCHudSystem2::ShowSubtitle` | 没有几何实体时的兜底 |

每个引擎调用都包在 SEH 里（`__try` / `__except`）。失败就记 `... EXCEPTION code=<n>` 并跳过
这条字幕，游戏照常跑。这是故意的：绝不能因为某个符号解析到了意料之外的东西，就让插件把游戏
带崩。

## 文本加载（`strings.pak`）

`ensure_text()` 是**懒**的：第一次真的要显示字幕时才加载：

1. `pak_path()` —— 从 `bin` 目录往上找（最多 4 层），找 `data\compiled\strings.pak`。
   这样 `bin\` 和嵌套的目录结构都能覆盖。
2. G3V0 归档：+4 处是 `G3V0` 魔数，后面是 `(name, offset, size, compressed)` 的目录项。
   插件只要 `svms.tab`。
3. `svms.tab` 这一项可能是 zlib 压缩的；插件自带一份最小 inflate（`inf_zlib`，RFC 1950
   包装 + RFC 1951 deflate，定长和动态 Huffman 都有）。不需要 zlib DLL。
4. TAB0 表：一种小型的多语言表格式。块是 UTF-16LE 字符串；名为 `svms` 的块放键，各语言块
   按键的顺序各放一个值。插件只为选中的那一列存 `key -> value`。

选列（`lang_to_col`）：

- 显式写 `Language=<名字>` 优先（`English` → `English_Text`，…）；
- 本身就长得像列名的值（`*_Text`）原样使用 —— 这是给自带新列的翻译补丁留的口子；
- `auto` 问 `eCLocAdmin2::GetVoiceLanguage()` 再映射。

如果游戏运行中语言变了（比如玩家在选项里切了语言），`init_thread` 会发现列名和已加载的不
一样，于是重读 pak。

填的列名在 pak 里不存在时，插件退回 `English_Text`，并在日志里写
`PAK column <x> missing, fallback English_Text` —— 所以 `Language=` 里写错字的表现是
「显示英文」，而不是「什么都不显示」。

`strings.pak` 完全读不到时，插件会退回旧的 JSON 文本包
（`AmbientVoiceSubtitles.zh.json` 或 `svms_zh.json`），前提是它存在，并在日志里说明用了它。
这条路径只为老安装留着；pak 才是权威。

## 配置

`AmbientVoiceSubtitles.ini` 用 `GetPrivateProfileIntA` / `GetPrivateProfileStringA` 读，
所以键值区必须保持纯 ASCII / ANSI 兼容（注释是 UTF-8，解析器不读）。文件不存在时，
`write_default_ini` 会把 `AVS_INI_TEMPLATE` 写到 `.asi` 旁边；那个数组由
`tools/gen_ini_template.py` 从 `config/AmbientVoiceSubtitles.ini` 生成，改默认文案的唯一
途径就是它。

`maybe_reload_config` 运行期会看文件的写入时间，所以改完几秒内就生效，不用重启。

## 兜底

- 说话者没有几何实体 → `hud_fallback()` 用 `gCHudSystem2::ShowSubtitle`（画面底部那种普通
  HUD 字幕）。比什么都没有强，而且万一 `AddScreenMessage` 哪天变了，功能也还能用。
- 没有 pak → 退回 JSON 文本包（见上）。
- 还没有渲染器实例 → 这条消息跳过，等下次 bark 再试。

## 踩过的坑

这些都是真花过调试时间的，改代码时请记着。

1. **不要在 `DllMain` 里读 `strings.pak`（也不要碰 `eCLocAdmin2`）。** 早期版本这么干过：
   抢在引擎文本子系统就绪之前拿住 pak 句柄，结果主菜单文字回退成 `HUD2_Label_PressStart`
   这类原始 ID。文本加载之所以是懒的，就是为了这个。
2. **`AddScreenMessage` 要真的几何实体。** 传 `NULL` 会当场崩：它第一件事就是调
   `eCGeometryEntity::GetWorldMatrix`。脚本实体必须经属性集转过去
   （`GetPropertySetAt(i)->GetGeometryEntity()`）。
3. **只投一次 `AddScreenMessage` 不够。** 渲染器每帧消费队列，所以插件从 `OnBeginFrame`
   挂钩里每帧重投。
4. **`bCString` 参数不是可以信任的、以 NUL 结尾的 C 字符串** —— 一律用 `read_bcstr`
   （`ReadProcessMemory`）去读，它不会崩。
5. **一切都按修饰名解析**，所以修饰名要和游戏版本保持同步；缺符号日志里会说
   （`api ... = 0000000000000000`）。
6. 插件只有 64 位（PE32+）；游戏也是 64 位。

## 调试

`bin\AmbientVoiceSubtitles.log`（每次运行都是追加写，旧运行的记录留在前面）里，一次运行
按顺序包含：

- `=== AmbientVoiceSubtitles v20 loaded pid=... ===`
- 解析到的 API 地址（`api addsmsg=... getinst=...`）
- `SAYSVM speaker=... svm="..."`
- `BARK key=SVM_..._... speaker=... text="..."`
- `PAK loaded: N keys, column=...`
- 虚表挂钩装好后有 `VT hooked OnBeginFrame slot=N`

第一行里的 `v20` 是开发迭代号，不是 MOD 的版本号（发布版是 1.0），日志写着 `v20` 就是最新版。

`NOKEY`、`NOSPEAKER`、`PAK not found`、`VT NOT hooked`、`... EXCEPTION code=` 是值得看的
失败行。要玩家在问题报告里提供什么，见给用户的安装说明（`安装说明.txt`）。
